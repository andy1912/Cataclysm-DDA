## 0. Executive summary

1. **Depend on `dda` and override it; don't replace core.** C++ holds ≥ 2,535 unique single-line `static const` id constants plus 66 multi-line ones, and ~600 inline id literals (§3.1). Only one core mod can be active (`src/mod_manager_ui.cpp:131-139`).
2. **Collision semantics differ by type** (§1.3):
   - **Replace** (or patch in place via same-id `copy-from`): generic_factory types.
   - **Extend unless `"override": true`**: `monstergroup`.
   - **Append**: `vehicle_group`/`vehicle_placement`/`vehicle_spawn`, and `talk_topic` responses.
   - **Additive weighted candidates**: `mapgen` and nested `mapgen`.
   - **First wins**: `npc`.
   - **Replace unless same-id copy-from**: `item_group`.
3. **The US-content toolbox** (§2):
   - `ITEM_BLACKLIST` (removal);
   - item `MIGRATION` (global substitution, including saves);
   - same-id reskin;
   - `MONSTER_*` lists;
   - singleton scenario/profession whitelists;
   - the region feature-flag whitelist, which filters the **random** overmap special batch and **region-random** map extras only (§2.1 lists bypasses);
   - replacing the `region_settings_city` pools.
4. **The plan's type names are wrong.** `COMESTIBLE`/`BOOK`/`TOOL`/`ARMOR`/`GENERIC` are not types. Use `"type":"ITEM"` + `"subtypes"` (`src/init.cpp:367`, `src/item_factory.cpp:3115-3190`). `doc/MODDING.md:274-293` documents a nonexistent `region_overlay`.
5. **C++ for Pass 1 is optional, except validation tooling.**
   - US traffic can be displaced with JSON only (§2.2).
   - C1 (`vehicle_group` override/delete) is a nice-to-have, needed only for exact removal.
   - **C6 has LANDED** (`2efb03fe98`). The curses `--check-mods` now runs, and `tools/saigon/check_mod.sh dda` reports `OK` ([RUNTIME-VERIFIED r3: `SAIGON_USERDIR=<scratch>/ud_dda tools/saigon/check_mod.sh dda` printed `Checking mod Dark Days Ahead [dda]` then `OK: dda`, rc 0; 3 min 32 s wall / 58 s user on a loaded machine (29% CPU)]).

### 1.2 `generic_factory<T>` inheritance [V]

`src/generic_factory.h`:
- `handle_inheritance` (`:245-287`): `copy-from` looks up real objects first (`:250-255`), then abstracts (`:256-260`), else defers (`:262-266`). `abstract` + `id` throws (`:271-275`).
- `insert` **replaces** a same-id object (`:392-414`, `result = obj` `:403`). A `mod_error` is thrown only if the same source defines an id twice (`src/mod_tracker.h:75-82`).
- `finalize` (`:418-431`) calls `load_deferred` (`src/init.cpp:186-218`). Leftovers get "JSON contains circular dependency" (`:205-211`), which usually means a `copy-from` typo.
- `relative`/`proportional` (`:797-900`). Container `extend`/`delete` via `generic_typed_reader` (`:1568-1603`). A plain member **replaces** the container (`:1574-1577`). `extend`/`delete` only apply with copy-from (`:1578-1583`).
- **Same-id patch idiom:** `"id": X, "copy-from": X`. Example: `data/mods/desert_region/region_settings/region_settings/desert_regional_map_settings.json:599-601`.

### 2.3 B10 decision rule: blacklist vs migration vs same-id reskin (D2)

| Situation | Use | Why / hazard |
|---|---|---|
| id is in §3.1 (C++-hardcoded), e.g. `water`, `battery`, `UPS` | **Same-id reskin** (`"id":X,"copy-from":X`, change name/description/variants; restate `subtypes` if touching slot fields) | Blacklist strips it from requirements (`src/item_factory.cpp:1700-1703`). | Item fine as-is but named/described as American | **Same-id reskin** | Cheapest, but R4 caution: text only. |
| Any case | Never migrate or blacklist an id that dda code creates directly | See R7/R14. |

### 8.2 Ordered steps

0. **C6 is LANDED.** Gate every unit on `tools/saigon/check_mod.sh saigon_2000s` → `OK`. Optionally land **C2**, so load errors exit cleanly (rc 1) instead of aborting.
1. B1 skeleton. Validate: `--check-mods saigon_2000s`, exit code, and grep for `Error loading data`.
2. B10a settings: whitelists + `GENERIC_*_ID`.
3. B2 scenario/EOC/snippets.
4. B8 overmap, mapgen, palettes with the `SAIGON` flag; region routing; own trails and extras.
5. B5/B7 items: `ITEM`+`subtypes`, restating `subtypes` in copy-from patches that touch slot fields. B10b: apply the §2.3 rule (MIGRATION for equivalents, blacklist for no-equivalents, reskin for hardcoded ids).
6. B9 monsters/NPCs: new npc ids; `"override": true` on redefined groups.
7. **B6 traffic via JSON routes (a)+(c), plus (d) for the hardcoded groups.** C1 only if exact removal is later required.
8. After each step: formatter, `--check-mods`, and `cata_test --mods=dda,saigon_2000s "[force_load_game]"` once built.

### 8.3 Idioms

- **Books:** same-id patch of dda recipe books, e.g. `{"type":"ITEM","id":"cookbook_daintydishes","copy-from":"cookbook_daintydishes","subtypes":["BOOK"],"name":…,"variants":[…]}`. **Restate `subtypes`** if any book-slot key (e.g. `max_level`, `time`) is changed (`src/item_factory.cpp:3175-3188`). `book_learn` has no `extend` (`src/recipe.cpp:472-481`). New mechanics still belong in new books and recipes.
- **Hardcoded item groups:** replace `forage_*`, `default_zombie_clothes`, `everyday_corpse`.
- **Names:** snippet category override (hunvre). `reload_names` re-reads `data/names` on language change (`src/text_snippets.cpp:97-126,186-193`; `src/translations.cpp:105`).
