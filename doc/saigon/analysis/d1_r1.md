## 0. Executive summary

1. **The renderer is SDL3's 2D `SDL_Renderer` ("gpu" driver preferred), not raw SDL_GPU.**
   - Sprites are `SDL_RenderTextureRotated` calls, one per sprite, into a terminal-sized `display_buffer` that is integer-upscaled on present (§1.1).
   - Shaders are **fragment-only** `SDL_GPURenderState`s: 8 `.frag` files, 0 `.vert`. They swap per `lit_level` variant, with pre-baked atlases as a fallback (§1.2).
2. **Frames are event-driven.** `ui_manager::redraw_invalidated` → `game::draw` → `wnoutrefresh(w_terrain)` → `curses_drawwindow` → `cata_tiles::draw`, identified by curses window identity. Presents are throttled to ≥ 25 ms apart (§1.1, §6.2).
3. **Layering is an implicit painter's order.** The loop runs z → screen row → 11 fixed layers → column, with no sort and no depth. Every sprite is resolved through string-keyed lookups and live map queries, and the draw path **mutates game state** (map memory, overmap seen) (§2.1).
4. **Only z ≤ viewer is drawn, and artificial light exists only on the viewer's z.** For 3–5 storey *nhà ống* streets this means façades appear one storey tall and lamps below are unlit (§2.2, §3.1).
5. **Lighting reaching the renderer is quantized.** It is `lit_level` (≈3 visual states) plus a colored tint. The directional `four_quadrants` light and the light-source list never reach the GPU (§3.2).
6. **Iso mode is a fixed 2:1 dimetric transform in 5 functions.** It has no rotation or vertical flip for sprites, no mask tint, no tests and no shipped tileset. The projection leaks into 14 gameplay/input call sites. `tile_iso` does not exist (§4).
7. **Seams.**
   - (A) a main-thread `frame_snapshot` + `commit_frame_side_effects`;
   - (B) a `render_backend` with `sdl_renderer_backend` (pixel oracle) and `sdl_gpu_backend`;
   - (C) batching that follows the in-tree `minimap_vertex_batch` → `SDL_RenderGeometryRaw` precedent;
   - (D/E) G-buffer and tileset layers (`normal_file`/`height_file`/`emissive_file`);
   - (F) native-resolution world target, projection-owned picking, and curses as a separate `world_view` (§5).
8. **Performance (measured).** One 3D FOV rebuild (`cast_zlight`) costs **6.9–19.2 ms** on this i5-7360U, measured under load. 60 fps movement is therefore CPU-bound before drawing, and frames must be decoupled from turns (§6).
9. **Roadmap.** R0 harness (tiles test binary, counters, headless golden screenshots) → R1 snapshot → R2 batched (then SDL_GPU) → R3 projection + upper-z cut-away → R4 per-pixel light and normal maps (cosmetic only, gameplay `lit_level` unchanged) → R5 shadows (§8).
10. **Pass 1 needs no renderer change.** The only rules are JSON ones: `light_color` on emitters with a per-OMT emitter cap, and `looks_like` on all new ids (§7).

### 1.2 Where the atlas and the shaders are applied [V]

- **Renderer choice.** `WinCreate` sets `SDL_HINT_RENDER_DRIVER` to `"gpu,direct3d12,direct3d11,opengl"` on Windows and `"gpu,opengl"` elsewhere, because "The GPU renderer is the only one that supports SDL_SetGPURenderState" (`src/sdltiles.cpp:659-686`). A Vulkan bias is applied when only `.spv` artifacts exist (`src/sdltiles.cpp:383-406`, `:673-684`). `shared_variant_pass` is created per renderer (`src/sdltiles.cpp:744`).
- **Shaders are fragment-only, attached to the SDL 2D renderer.** `cata_shader::shader::load_fragment` picks `.spv`/`.dxil`/`.msl` from `SDL_GetGPUShaderFormats` and calls `SDL_CreateGPUShader` (`src/cata_shader.cpp:73-155`). `render_state::create` wraps it in `SDL_CreateGPURenderState` (`src/cata_shader.cpp:203`). The device comes from `SDL_GetGPURendererDevice( renderer_ )` (`src/cata_shader.cpp:696`). There is **no custom vertex shader, no custom vertex format, no instancing, no depth buffer and no MRT**. `[GREP]` `ls data/shaders` = 8 `.frag` files, **0 `.vert`**: `grayscale, memory_blue_dark, memory_darken, memory_sepia_dark, memory_sepia_light, nightvision, overexposed, tint`.
- **Variant selection.** `variant_kind { NORMAL, SHADOW, NIGHT, OVEREXPOSED, MEMORY }` (`src/cata_shader.h:48-55`). `draw_sprite_at` computes `compute_variant_kind( rp.ll, rp.use_night_vision_tiles )` and calls `vp->try_begin( variant, m_zlev_tint_bound )` (`src/cata_tiles.cpp:2750-2766`). `try_begin` only calls `SDL_SetGPURenderState` when the state changes (`src/cata_shader.cpp:761-806`; contract `src/cata_shader.h:175-194`). Per-variant states are used instead of uniforms, because "per-call uploads leak host memory on the GPU renderer without recycling" (`src/cata_shader.h:169-173`).
- **Atlas fallback.** When the shader is not bound, the sprite texture is swapped for a pre-baked variant atlas: `get_memory_tile` / `get_overexposed_tile` / `get_night_tile` / `get_shadow_tile` (`src/cata_tiles.cpp:2768-2789`). The tileset keeps six parallel `std::vector<texture>`: `tile_values, shadow_, night_, overexposed_, memory_, silhouette_tile_values` (`src/cata_tiles.h:316-321`).
- **Bake plan.** `atlas_bake_plan` decides which variants to pre-bake. Variants are skipped only if the shader path can generate them (`src/atlas_bake_plan.h:17-43`). `resolve_atlas_bake_plan` honours `CATA_FORCE_ATLAS_VARIANTS` (`src/sdltiles.cpp:533-566`), `CATA_DISABLE_SPRITE_SHADERS` is read in `variant_pass::probe` (`src/cata_shader.cpp:684`), and `CATA_DISABLE_TINT_OVERLAY` in `tint_overlay_disabled` (`src/cata_tiles.cpp:580-585`). The upload is `tileset_cache::loader::upload_atlases`, which logs `atlas upload:` (`src/tileset_loader.cpp:1013`, `:1148`).
- **Colored-light tint.** The per-tile tint (`tile_tint`, `src/tile_tint.h:10-16`) is encoded into the texture color/alpha mod (`tint_texture_mod_for`: rgb = hue, a = 255−strength, `src/tile_tint.cpp:36-44`). It is applied with `SetTextureColorMod/AlphaMod` around the blit and reset afterwards (`src/cata_tiles.cpp:2879-2886`, `:2957-2962`). `tint.frag` decodes it as `mix( sample.rgb, v_vertex_color.rgb, 1 − v_vertex_color.a )` (`data/shaders/tint.frag`). Without shaders, ortho tiles fall back to a **silhouette-mask render-to-texture pass** (`flush_tint_batch`, `src/cata_tiles.cpp:1224-1321`) or flat rects (`:1339-1359`).
- **Frame-end flush.** `vp->flush()` at the end of `cata_tiles::draw` (`src/cata_tiles.cpp:1578-1589`). Before any untextured draw it goes through `flush_sprite_shader_for_untextured_draw` (`src/cata_tiles.cpp:4092-4100`), which is called by `draw_zlevel_overlay`, `draw_square_below` and the frame clear.
- **Recovery machinery.** `renderer_resource_coordinator`, `display_buffer_draw_scope` and `present_gate` (`src/sdltiles.cpp:1218-1295`, `:967-978`, `:1342-1406`) wrap every target switch. Any R2 backend must inherit this device-lost/resize contract. It is tested headless by `tests/renderer_recovery_test.cpp` with a software renderer (`renderer_recovery_test_support::setup_software_renderer`, `src/sdltiles.cpp:2151`).

**Runtime:** whether the `gpu` driver is actually selected on a given Mac, and the batching SDL does internally across `SDL_RenderTextureRotated` calls, are UNVERIFIED (no tiles binary). `config/debug.log` `atlas upload:` / `SDL renderer in use:` lines (`src/sdltiles.cpp:427`) are the intended evidence for R0.

## 2. Q2 Sprite layering model, z-levels, curses coupling, caches

### 2.1 Two-phase draw: "draw points" then immediate-mode emission [V]

**Phase A: draw-point generation (cached).** This runs only when `here.draw_points_cache_dirty` (`src/cata_tiles.cpp:751`). The cache lives on `map`, not on `cata_tiles`: `std::map<int, std::map<int, std::vector<tile_render_info>>> draw_points_cache` keyed by z, then screen row (`src/map.h:2428-2434`). `tile_render_info` = `common { pos, height_3d, bounds, tint_sprites, needs_tint, tint_color }` + `std::variant<vision_effect, sprite{ ll, invisible[5] }>` (`src/map.h:352-392`).

For each screen `(row, col)`, `tile_to_player` finds the map tile, then walks **downward** from `center.z()` to `draw_min_z = max( you.posz() − fov_3d_z_range, −OVERMAP_DEPTH )` (`src/cata_tiles.cpp:654`, `:777-1019`). It stops at the first tile where `map::dont_draw_lower_floor` is true, i.e. `floor_cache` (`src/cata_tiles.cpp:1015`; `src/map.cpp:7984-7993`). `fov_3d_z_range` is a compile-time `10` (`src/game_constants.h:28`). Debug overlays (scent, radiation, temperature, snow, lighting, transparency) are also materialized here into `overlay_strings_cache` / `color_blocks_cache` (`src/cata_tiles.cpp:821-990`).

**Dirty triggers** (the cache survives idle redraws, e.g. animated tiles):
- `game::get_player_input` sets it once per player input (`src/handle_action.cpp:280`);
- `map::build_map_cache` sets it when the seen cache is rebuilt (`src/map.cpp:10842-10854`);
- `map::update_visibility_cache` sets it (`src/map.cpp:7755-7759`);
- a viewport change (`prev_top_left`/`prev_o`) sets it (`src/cata_tiles.cpp:701-707`).

**Phase B: emission (every redraw).** The loop order is:

```
for z in [center.z − fov_3d_z_range … center.z]            // src/cata_tiles.cpp:1044-1053
  for row in screen rows                                   // :1063
    prepass: tint eligibility per tile                     // :1076-1112
    for layer f in drawing_layers[11]                      // :1026-1033, :1120
      for tile p in draw_points_cache[z][row]              // :1123
        (this->*f)( p.pos, ll, p.height_3d, invisible )
    tint overlay for the row (mask path, no shader)        // :1174-1416
```

The 11 layers, in order: `draw_terrain, draw_furniture, draw_graffiti, draw_trap, draw_part_con, draw_field_or_item, draw_vpart_no_roof, draw_vpart_roof, draw_critter_at, draw_zone_mark, draw_zombie_revival_indicators` (`src/cata_tiles.cpp:1026-1033`). Stacking height accumulates in `height_3d += tile.height_3d` (`src/cata_tiles.cpp:2966`) and shifts later sprites up (`destination.y … − height_3d`, `:2806`).

**Sorting model.** There is no sort and no depth buffer. The order is an implicit painter's algorithm: z ascending, then screen row ascending, then layer, then column. It is correct only when:
- (a) no sprite reaches into a *later* row's footprint downwards; and
- (b) within a row, the layer order is the depth order.

Things that break (b) cannot be expressed at all: a tall furniture sprite in front of a creature on the same row, a vehicle roof over a creature, or an item on a table.

**Per-tile draw calls.** Every layer resolves a sprite by string id through `draw_from_id_string_internal` (`src/cata_tiles.cpp:2387`). Each call can do:
- `find_tile_looks_like` with string concatenation (`id + "_transparent"` `:2428`, `id + "_int" + std::to_string(...)` `:2438`, variant suffixes `:2008-2020`);
- an `unordered_map<std::string, tile_type>` lookup (`src/cata_tiles.h:345`);
- a `get_option<bool>( "NV_GREEN_TOGGLE" )` string lookup (`src/cata_tiles.cpp:2394`).

It then calls `draw_tile_at` → `draw_sprite_at` twice (bg and fg, `src/cata_tiles.cpp:2970-2981`). Each is one `SDL_RenderTextureRotated`. There is no instancing and no explicit batching. Whether SDL3's GPU renderer merges consecutive same-texture draws into one GPU draw is UNVERIFIED. Tinted sprites toggle `SetTextureColorMod` on the shared atlas texture before and after each draw (`src/cata_tiles.cpp:2879-2886`, `:2957-2962`).

**Game state mutated inside draw.** This matters for a snapshot or thread split.
- The per-frame "memorize" loop re-calls `draw_terrain/furniture/trap/part_con/vpart_*` with `memorize_only = true` over the whole view (`src/cata_tiles.cpp:1466-1500`). It writes avatar map memory through `memorize_terrain` (`src/cata_tiles.cpp:3136`) and `memorize_clear_decoration` (`:1491`).
- `draw_terrain` sets `memory_cache_ter_set_dirty` (`src/cata_tiles.cpp:3130`).
- `you.prepare_map_memory_region(...)` (`src/cata_tiles.cpp:708-711`) runs from the draw call.
- `map::update_visibility_cache` writes `overmap_buffer.set_seen` (`src/map.cpp:7750`).

### 2.2 z-level rendering ("draw lower levels") [V]

- Only levels ≤ `center.z()` are drawn (`while( cur_zlevel <= center.z() … )`, `src/cata_tiles.cpp:1053`). **Nothing above the viewer is ever rendered.** For the Saigon *nhà ống* (3–5 storeys, shared z3 roof walks per d2_r3.md), a player at z0 sees only a cut-away ground floor; upper storeys and balconies appear only when the player climbs.
- Lower levels are pushed down by `height_3d = ( cur_zlevel − center.z() ) * zlevel_height` (`src/cata_tiles.cpp:1078`). Ortho tilesets usually set `zlevel_height = 0` (`src/tileset_loader.cpp:396` default 0), so lower levels overlap in place. Where no sprite exists, open air gets a fog rect (`draw_zlevel_overlay`, `src/cata_tiles.cpp:4102-4149`; alpha `fog_alpha`, `:519-520`). Fog is an untextured draw and so forces a shader flush per call (`:4104`).
- **Inconsistency.** Draw-point generation bounds lower levels by `you.posz()` (`src/cata_tiles.cpp:654`) but emission by `center.z()` (`:1044`). With `view_offset.z ≠ 0` (look-up/down), the two differ. Visual effect UNVERIFIED.
- The lightmap (artificial lights) is built **only for the viewer's z-level**: `generate_lightmap( zlev )` has a single caller (`src/map.cpp:10911`). This is confirmed by the comment "light map is not calculated outside the player character's z-level" (`src/character.cpp:2680-2684`). Other levels get sunlight only, via `build_sunlight_cache` (`src/lightmap.cpp:366-420`). So lamps on a lower floor seen through a stairwell/atrium are not lit.

### 2.3 Coupling to ASCII/curses [V]

- The tiles build is a **curses emulator**. `cata_cursesport::WINDOW` holds `std::vector<curseline>` cell buffers (`src/cursesport.h:59-84`). `catacurses::wnoutrefresh` → `curses_drawwindow` (`src/cursesport.cpp:179-187`) chooses a renderer **by window identity**: `w == g->w_terrain && use_tiles` → `tilecontext->draw` (`src/sdltiles.cpp:3653`). The tiled map is therefore a special case inside a text-window compositor.
- The map viewport size is computed in **font cells** and converted: `TERRAIN_WINDOW_WIDTH` via `to_map_font_dimension` (`src/game.cpp:3208`, `src/sdltiles.cpp:6758-6762`). `POSX/POSY` are the curses center (`src/game.cpp:3211-3212`). `cata_tiles::draw` subtracts `POSX, POSY` in ortho (`src/cata_tiles.cpp:626`).
- Game code still writes to the curses map window in tiles mode: `game::draw_critter` → `Creature::draw( w_terrain … )` (`src/game.cpp:3523`), `draw_veh_dir_indicator` → `mvwputch` (`src/game.cpp:3605-3611`), and async anims/blinks (`game::draw_async_anim_curses` / `draw_blink_curses`, `src/game.cpp:3302`, `:3335`). `map::draw` and `map::drawsq` early-return on `is_draw_tiles_mode()` (`src/map.cpp:7825`, `:7954`).
- Coupling size [GREP]: `defined( TILES )` appears 203 times in 65 files under `src/`. `tilecontext->` is used outside `sdltiles.cpp`/`cata_tiles.cpp` in 11 files, led by `src/animation.cpp` (26), `src/game.cpp` (17) and `src/options.cpp` (12).
- Animations are **blocking loops on the game thread**. `basic_animation::progress()` calls `ui_manager::redraw_invalidated(); refresh_display();` and then sleeps in 100 ms pump slices (`src/animation.cpp:55-80`). Tiles-side state is set through `tilecontext->init_explosion/init_draw_bullet/...` (`src/animation.cpp:312`, `:540`, `:606`, `:699`, `:805`).
- ImGui UIs render into the same `display_buffer` in the same `redraw_invalidated` pass (`src/ui_manager.cpp:398-403`, `:551`; `src/cata_imgui.cpp:581-587`).

### 3.2 How light reaches the renderer today [V]

1. **Discrete level.** `ll = ch2.visibility_cache[x][y]`, stored in the draw point (`src/cata_tiles.cpp:815`, `:1012-1013`).
2. **Variant.** `compute_variant_kind( ll, nv )`: MEMORIZED → MEMORY, NV → NIGHT/OVEREXPOSED, LOW → SHADOW, else NORMAL (`src/cata_tiles.cpp:182-196`). The variant picks a shader (`try_begin`) or a pre-baked atlas (§1.2). **LIT and BRIGHT draw identically.** There is no continuous brightness.
3. **Colour.** A per-tile `tile_tint` from `light_color_cache` and `lm.max()` (`src/cata_tiles.cpp:1090-1101`; `compute_tile_tint` `src/tile_tint.cpp:7-34`, strength capped at 80/255). It travels as vertex colour into `tint.frag` / `grayscale.frag` (§1.2).
4. **Vision effects.** Tiles that are not CLEAR get a flat `apply_vision_effects` sprite (`src/cata_tiles.cpp:2988`).
5. **Unused by the renderer.** The four quadrant intensities in `lm` (the only directional light information) and the source list are never passed to the renderer.

Lighting is therefore **per-tile, flat-shaded, and quantized to ~3 visual states plus tint**. Tile-edge light gradients do not exist.

### 4.2 Coordinate transforms (fixed 2:1 dimetric, one fixed camera yaw) [V]

- `player_to_tile`: `col = y + x + W/2 − o.y − o.x`, `row = y − x + H/2 − o.y + o.x` (`src/cata_tiles.cpp:1775-1792`).
- `player_to_screen`: `left = (col−1)·tw/2`, `top = (row+1)·tw/4 − th` (`src/cata_tiles.cpp:1794-1811`). **The base diamond is `tile_width × tile_width/2`; `tile_height` is only sprite height.**
- Inverse `tile_to_player` rejects half the (col,row) lattice by parity (`src/cata_tiles.cpp:1739-1761`). Visible-range math is in `get_window_base_tile_counts` / `get_window_any_tile_range` (`src/cata_tiles.cpp:1621-1709`). The z-shift is `z_height = zlevel_height · z` (`:1683`).
- Mouse picking `screen_to_player` assumes rhombus tiles: "TODO: maybe let tilesets provide the exact shape of the base tile" (`src/cata_tiles.cpp:1833-1893`, TODO at `:1854`).
- The origin differs by mode: `o = center` in iso vs `center − (POSX,POSY)` in ortho (`src/cata_tiles.cpp:626`).
- Minimap has its own iso projector (`pixel_minimap_iso_projector::get_tile_pos`, `src/pixel_minimap_projectors.cpp:67-73`).

### 4.3 Draw order in iso [V]

- Same loop as ortho (§2.1). A screen row is a diagonal `y − x = const`, rows go ascending, so back-to-front holds for sprites no wider than `tile_width`. Each z-level gets its own row range (`z_any_tile_range[center.z − z]`, `src/cata_tiles.cpp:632-636`, `:1054-1055`).
- Lower z are drawn first and shifted down by `zlevel_height` (`src/cata_tiles.cpp:1078`, `:2806`).
- **Occlusion helper.** Distance-based "retract" and `_transparent` sprite swap for tiles near the view center (`src/cata_tiles.cpp:2405-2432`). The distance in iso is `o.distance( pos )` (`:2411`). This is the only wall-cutaway mechanism, and it is radial, not camera/visibility-aware.

### 4.4 Bugs and limits [V unless marked]

1. **No sprite rotation or vertical flip in iso**: "never rotate isometric tiles" / "never flip isometric tiles vertically" (`src/cata_tiles.cpp:2911`, `:2922`, `:2941`). Rotating objects (vehicles, doors) need pre-drawn directional sprites. Vehicles have up to 24 facings (15° steps, UNVERIFIED for this fork), so iso vehicles are visually wrong unless the tileset supplies the rotations.
2. **No colored-light mask path in iso**: "Iso has no silhouette mask path, so only the sprite shader tints it" (`src/cata_tiles.cpp:1059-1061`). The fallback draws axis-aligned `tile_width × tile_height` rects, not diamonds (`:1186-1201`).
3. **Weather drops ignore z and projection**: "TODO: Z-level awareness" (`src/cata_tiles.cpp:4817`). Iso drops are generated over the whole `MAPSIZE_X × MAPSIZE_Y` bubble with zero offset (`src/handle_action.cpp:310-317`). With `dropCount = iEnd.x·iEnd.y·factor` (`:322`), that is 17,424·factor drop sprites per animation frame in iso. For Saigon monsoon rain (d3_r1.md) this is the worst case.
4. **Projection leaks into gameplay/input code** (`[GREP]` 15 call sites of `is_tileset_isometric()` besides its definition, 14 of them outside `src/sdltiles.cpp`):
   - movement key rotation: `get_movement_action_from_delta` (`src/action.cpp:543`, `:576`), `input_context` (`src/input_context.cpp:609`);
   - view shift (`src/handle_action.cpp:2113`);
   - mouse edge scroll (`src/game.cpp:2556`);
   - advanced inventory panes (`src/advanced_inv.cpp:259`);
   - sprite facing written into game state: `monster::facing`, `you.facing` (`src/monmove.cpp:1265`, `src/ranged.cpp:3346`, `src/avatar_action.cpp:307`);
   - construction preview (`src/construction.cpp:808`, `:865`);
   - `output.cpp` iso direction mapping (`src/output.cpp:2619`, `:2666`).
5. **Memorization skips iso on-screen tiles** in the memorize loop (`src/cata_tiles.cpp:1470`). It relies on the draw loop having memorized them.
6. **Nothing above the viewer is drawn** (§2.2). In iso this is the key visual gap for multi-storey Saigon streets: shophouse façades read as one storey. A real 2.5D view needs upper z drawn with cut-away (roof/upper-wall fade) around the player.
7. **Fog alpha is a function of `zlevel_height`** (`src/cata_tiles.cpp:519-520`). Fog is an untextured rect per open-air tile, which flushes the shader state per call (`src/cata_tiles.cpp:4102-4104`).

### 4.5 Is it a viable seam for 2.5D?

**Partly.** Its value is that it proves the game logic tolerates a non-ortho projection: input rotation, facing and picking already branch on it. The *math* is also isolated in 5 functions (`get_window_base_tile_counts`, `get_window_any_tile_range`, `tile_to_player`, `player_to_tile`, `player_to_screen`, `screen_to_player`). It is **not** a rendering architecture to build on:
- painter's order per row+layer, no depth;
- fixed yaw, and the iso flag is a `bool` rather than a projection object;
- no upper-z rendering;
- no tests.

**Recommendation (R3).** Replace `bool tile_isometric` with a `projection` strategy (`ortho`, `dimetric_2to1`, later `rotatable_dimetric(yaw)`) that owns those 5 functions. Cover it with headless round-trip tests (`screen_to_player( player_to_screen( p ) ) == p` for all p in view, both modes). Route the 14 non-renderer call sites through one `game::view_rotation()` query so a rotatable camera changes one place.

## 5. Q5 Refactoring seams (render_backend)

Design principle: **game state → (main thread) frame snapshot → (any thread) backend**. The backend never calls `get_map()`, `get_avatar()`, `g->` or options.

### 5.1 Seam A: frame-data extraction (snapshot) vs direct map queries

**Today.** Emission queries live game state per tile per layer: `here.ter`, `field_at`, `maptile_at`, `creature_at`, `you.sees`, map memory, and string-keyed sprite lookup (§2.4 item 7). It also mutates state (§2.1, last paragraph). The only data boundary is `draw_points_cache` (position, `lit_level`, `invisible[5]`, tint), and it stops short of *what* to draw.

**Cut.** Promote the draw-point generator (`src/cata_tiles.cpp:751-1020`) plus the per-layer "what to draw" logic (`draw_terrain` `:3099`, `draw_furniture` `:3188`, `draw_trap` `:3289`, `draw_part_con` `:3376`, `draw_graffiti` `:3394`, `draw_field_or_item` `:3416`, `draw_vpart` `:3686`, `draw_critter_at` `:3777`, `draw_entity_with_overlays` `:4151`, `:4221`) into a pure producer:


- **`sdl_renderer_backend`** (R1/R2 baseline) wraps today's primitives: `texture::render_copy_ex` (`src/cata_tiles.h:185-190`), `variant_pass::try_begin/flush` (`src/cata_shader.h:254-260`), the geometry rect (`src/sdl_geometry.h:47-52`), and the tint-mask batch (`src/cata_tiles.cpp:1224-1321`). It must reproduce today's pixels exactly: that is the regression oracle.
- **`sdl_gpu_backend`** (R2+) owns the `SDL_GPUDevice`, graphics pipelines with **our own vertex + fragment shaders**, an instance buffer, depth, and MRT. Two options:
  - (a) Today's device through `SDL_GetGPURendererDevice` (`src/cata_shader.cpp:696`), drawing into a GPU texture that the 2D renderer then composites. Interop between a raw SDL_GPU pass and `SDL_Renderer` command ordering is UNVERIFIED. Treat it as a spike.

- **Intermediate option that stays inside `SDL_Renderer`.** `SDL_GPURenderStateCreateInfo` exposes `num_sampler_bindings`, `num_storage_textures` and `num_storage_buffers` (set to 0 today, `src/cata_shader.cpp:195-201`).   - still no custom vertex attributes, so no world position except by reconstructing from `gl_FragCoord` (needs a camera uniform);
  - per-call uniforms are avoided because they "leak host memory" (`src/cata_shader.h:169-173`).
  - Runtime feasibility UNVERIFIED. It is a good **R4a spike** before committing to (a)/(b).
- **Recovery contract.** Every backend must honour `renderer_resource_coordinator` / `display_buffer_draw_scope` / `present_gate` (`src/sdltiles.cpp:1218-1295`, `:967-978`) and the atlas replay (`tileset_cache::loader::upload_atlases`, `src/tileset_loader.cpp:1013`). Validation: `tests/renderer_recovery_test.cpp` (36 `TEST_CASE`s, `[GREP]`) must pass for each backend.

### 5.3 Seam C: batching and instancing on SDL3 GPU

**Today.** 1–2 `SDL_RenderTextureRotated` calls per layer per tile (§2.1). The state changes that split batches are:
- shader state switches (`try_begin`, `src/cata_shader.cpp:761-806`);
- untextured fog/rect flushes (`src/cata_tiles.cpp:4092-4104`);
- atlas texture changes;
- color-mod toggles on tinted tiles.

There is a working in-tree precedent for CPU vertex batching: `minimap_vertex_batch::append_quad` → `render_batch` → `SDL_RenderGeometryRaw` (`src/pixel_minimap_geometry.h:13-18`, `:57`; `src/pixel_minimap_geometry.cpp:131-133`; wrapper `RenderGeometryRaw` → `SDL_RenderGeometryRaw` `src/sdl_wrappers.cpp:487-500`), with headless tests in `tests/pixel_minimap_geometry_test.cpp`.

**Plan.**
- **R2a (no new API).** Emit `sprite_instance { dst rect, uv rect, atlas page, variant, tint, rota/flip, depth }` into a vector. Stable-sort by (z, row, layer, col) to preserve today's order exactly. Then coalesce runs of the same (atlas page, variant, blend) into one `SDL_RenderGeometryRaw` call carrying 4 vertices per sprite, with tint in vertex colour (already the shader contract, `data/shaders/tint.frag`). Rotation and flip become UV/vertex permutation (90° steps only, `src/cata_tiles.cpp:2846-2869`). Expected draw-call reduction from ~2 per layer-tile to ~(#atlas pages × #variants) per z-level: UNVERIFIED until R0 counts.
- **R2b (SDL_GPU).** One instanced draw per (pipeline, atlas page). The instance buffer is uploaded with a transfer buffer per frame. Depth is written from `(z, row, height_3d)`, so the painter's order is no longer load-bearing and mixed-layer occlusion (§2.1 "breaks (b)") becomes correct.

### 5.4 Seam D: normal-map and shadow-map passes

- **G-buffer (R4)**: albedo (existing atlas), normal (new atlas layer, same UV), height/depth (new layer, per-pixel height above tile base), emissive (new layer). Same `sprite_instance`, different pipelines/MRT.
- **Lighting pass (R4)**: full-screen or tiled light accumulation from `light_record`s. The `lit_level` visibility mask comes in as a texture so hidden tiles stay hidden (§3.3 "Gameplay/visual consistency").
- **Shadows (R5)**:
  - Sun/moon: one directional shadow via ray-march over a height field built from `occupancy_grid`. Source data: `floor_cache` and `transparency_cache` per z (`src/level_cache.h:42-56`) plus a per-terrain "wall height" property.
  - Point lights: screen-space 2D shadows, or reuse the CPU `castLight` result as a per-light visibility mask for the first iteration.
  - Days and time come from existing `g->natural_light_level` / `dawn_dusk_color_for_lightmap` (`src/lightmap.cpp:544`, `:553`).

### 5.5 Seam E: tileset format extensions

- **Where.** `tileset_cache::loader::parse_atlases` reads `tiles-new[].file` (`src/tileset_loader.cpp:524-533`). It records an `atlas_replay_descriptor { image_path_u8, sprite_width/height, atlas_offset, expected_tilecount }` (`src/cata_tiles.h:280-289`) that `upload_atlases` replays (`src/tileset_loader.cpp:1013`).
- **Extension (backwards compatible, all optional).**
  - Per `tiles-new` entry: `"normal_file"`, `"height_file"`, `"emissive_file"`. Same grid and sprite size as `"file"`, so sprite indices stay 1:1.
  - `atlas_replay_descriptor` gains 3 optional paths.
  - `tileset` gains parallel `normal_tile_values`/… vectors, like the six existing variant vectors (`src/cata_tiles.h:316-321`).
  - `tile_info` gains `"projection": "ortho" | "dimetric"` (supersedes `"iso"`, which stays readable), `"base_tile": [w, h]` (fixes the rhombus TODO `src/cata_tiles.cpp:1854`) and `"camera_yaws": [0,90,180,270]`.

### 6.2 Per-frame cost model today (reading-based; magnitudes UNVERIFIED, no tiles binary)

Definitions:
- **C** = drawn cells. For ortho 32 px at 1920×1080, C ≈ 60 × 34 ≈ 2,040. Iso with `tile_width` 64 gives ≈ `(1920·2/64+1)·(1080·4/64+1)/2` ≈ 2,100 per z (`src/cata_tiles.cpp:1657-1658`).
- **Z̄** = mean z-levels per column before `dont_draw_lower_floor` stops. It is ≈1 at street level; 2–4 on a z3 roof walk over an alley (d2_r3.md).
- **S̄** = sprites per cell-layer hit: terrain bg+fg = 2, plus furniture, items, fields and vehicle parts. A character is 1 base sprite plus one per worn/wielded overlay (`draw_entity_with_overlays` `src/cata_tiles.cpp:4151-4219`).

Costs:
- **Emission:** `11 layers × C·Z̄` layer calls. Each does map queries and a string-keyed lookup (§2.4). Draws are ≈ `C·Z̄·S̄`. For a dense Saigon street with parked motorbikes, vendors' carts and crowds, a rough 3 sprites/cell × 2,000 cells × 1.5 z ≈ **9,000 `SDL_RenderTextureRotated`/frame** (estimate).
- **Memorize loop:** another `(2·MAX_VIEW_DISTANCE+1)²` = 121² = 14,641 `draw_terrain(memorize_only)` calls **per redraw**, bounded by `min_visible..max_visible` (`src/cata_tiles.cpp:652-653`, `:1466-1500`). Each does `get_connect_values`/`get_terrain_orientation`. This scales with **view range, not screen size**, and is paid even on idle animation redraws.
- **`build_map_cache` fixed part:** 21-level dirty scans plus the per-call `std::vector`/`std::set` allocations (§2.4 item 4).
- **Present:** `RenderCopy` of the display buffer plus `RenderPresent` (`src/sdltiles.cpp:1022-1038`), throttled to ≥ 25 ms apart via `try_sdl_update` (`src/sdltiles.cpp:125`, `:1042-1050`). **Today the tiles build cannot exceed 40 Hz on the throttled path.** The direct `refresh_display()` calls from `get_input_event` (`:6470-6471`) bypass the throttle.

### 6.3 Budget at 60 fps for a dense multi-z Saigon view (targets for R2–R5)

| Stage | Thread | Target | Basis |
|---|---|---|---|
| Turn simulation incl. `build_seen_cache` / `generate_lightmap` | main | **outside the frame budget** (per turn); hitch ≤ 33 ms | measured 7–19 ms FOV alone (§6.1) |
| `build_frame_snapshot` (C·Z̄ ≈ 3–8k cells, memo'd sprite resolution) | main, per turn / on dirty | ≤ 4 ms | replaces draw-point generation + per-layer queries |
| Idle-frame reuse of snapshot (animations, flicker, rain) | render | ≤ 0.5 ms CPU | no map access |
| Instance build + stable sort (≈ 10–25k instances) | render/worker | ≤ 1.5 ms | radix sort on 64-bit key |
| GPU submission (instanced, ≤ 64 draw calls) | render | ≤ 1 ms CPU | vs ≈ 9k calls today |
| G-buffer + lighting (≤ 64 lights) + sun shadow ray-march at 1080p | GPU | ≤ 6 ms on integrated GPU | UNVERIFIED; measure in R4/R5 |
| ImGui + UI text + present | render | ≤ 2 ms | |

### 6.4 What can move off-thread, given thread safety [V]

- **Nothing that touches game state.**
  - `get_map()`, `get_avatar()`, `g`, `get_option<>` are unsynchronized globals.
  - The draw path uses function-local statics: `lighting_colors` (`src/cata_tiles.cpp:951`), `player_prev_pos` / `player_prev_range` (`src/map.cpp:10839-10840`), `cached_char_lights` (`src/map.cpp:10893`), `previous_turn` (`src/game.cpp:3416`).
  - The only `std::thread` in `src/` is in `sounds.cpp` (`src/sounds.cpp:1433`) `[GREP]`.
  - `build_frame_snapshot` and `commit_frame_side_effects` must stay on the main thread.
- **Safe to move after R1:** everything that consumes an immutable `frame_snapshot`:
  - instance building, sorting, light-grid upload preparation, shadow height-field build from `occupancy_grid`;
  - GPU command recording. SDL3 thread rules for `SDL_Renderer` (main thread) versus SDL_GPU command buffers are UNVERIFIED here, and must be checked against the SDL3 headers before R2b.
- **Parallelizable inside the simulation (optional, gameplay-owned, not renderer work).**
  - `cast_zlight` octants and z-directions write overlapping `seen_cache` cells with max-accumulate. Use per-thread buffers plus a max-reduce.
  - `generate_lightmap` sources do `elementwise_max` into `lm` (`src/lightmap.cpp:1455`). Use per-thread `lm` plus a reduce.
  - Both are deterministic under max-reduce.
  - Validation: `tests/shadowcasting_test.cpp` `[shadowcasting]` cases and `tests/vision_test.cpp` must be bit-identical.
- **Frame/turn decoupling.** `input_manager::get_input_event` busy-waits with `SDL_Delay(1)` (`src/sdltiles.cpp:6476-6500`). That wait is the natural place for a fixed-rate render tick that re-presents the cached snapshot. Only the `ui_adaptor` redraw needs the main thread.

- **(iii)** Every phase ends with the validation listed, and `tests/cata_test` (curses) plus a tiles test binary green.

Log one `render stats:` line per N frames to `debug.log`, modelled on `atlas upload:` (`src/tileset_loader.cpp:1148`).

### R1: Frame snapshot (decouple game state from drawing)

- **Seam.** §5.1: `build_frame_snapshot` / `commit_frame_side_effects`, called from `game::draw` after `build_map_cache` / `update_visibility_cache` (`src/game.cpp:3381-3382`). `cata_tiles::draw` and `curses_world_view` consume the snapshot.
- **Steps.**
  1. Move the side effects (memorization, `prepare_map_memory_region`, memory dirty bits) out of draw.
  2. Memoize sprite resolution.
  3. Snapshot = today's `draw_points_cache` + resolved layers + `light_record`s + overlays.
  4. `cata_tiles::draw` renders only from the snapshot. The legacy per-layer functions become snapshot *builders*.
  5. Key dirtiness on `map_epoch`/turn.
  6. Remove per-frame allocations (§2.4 items 1–6).
  7. Idle frames re-present the cached snapshot.
- **Validation.**
  - Golden screenshots identical to R0 (0-diff, legacy backend).
  - Snapshot hash test in curses `cata_test`.
  - `tests/map_memory_test.cpp`, `tests/vision_test.cpp` green.
  - R0 counters: layer-call map queries → 0 during emission.
  - Idle-frame CPU ≤ 0.5 ms.
- **Risk.** Medium. Map memory semantics (memorize-on-draw) are subtle, see `memory_cache_dec_is_dirty` (`src/cata_tiles.cpp:1489-1495`). Upstream edits to `draw_*` layer functions will conflict, so keep the builders structurally parallel to them to ease 3-way merges.

### R2: Batched renderer (then SDL_GPU)

- **Seam.** §5.2 `render_backend` + §5.3 batching. `sdl_renderer_backend` first.
- **Steps.**
  - **R2a:** `sprite_instance` stream → stable sort (z,row,layer,col) → `SDL_RenderGeometryRaw` runs per (atlas page, variant). Tint rides in vertex colour. The pattern is proven by `minimap_vertex_batch` (`src/pixel_minimap_geometry.h:13-18`).
  - **R2b:** `sdl_gpu_backend` with owned pipelines (vertex + fragment), an instance buffer, and a depth buffer from `(z,row,height_3d)`. Run the interop spike (§5.2 options a/b) first.
- **Validation.**
  - R2a golden screenshots within 2 LSB of legacy.
  - R0 counters: draw calls ≥ 20× lower (target; UNVERIFIED).
  - `tests/renderer_recovery_test.cpp` passes with the new backend (device reset, resize, pause).
  - Frame time on the Saigon benchmark map ≤ 16.7 ms CPU on the reference machine.
- **Risk.** High for R2b: SDL_GPU/SDL_Renderer interop, the ImGui backend swap, and shader-format build (spv/msl/dxil via `shadercross`, `doc/c++/COMPILING.md:156-158`). Mitigation: R2a alone delivers most of the CPU win with no new API.

### R3: Iso / 2.5D projection

- **Seam.** A `projection` object replaces `bool tile_isometric` and owns the 5 transform functions (§4.5). The 14 non-renderer `is_tileset_isometric()` call sites go through `game::view_rotation()`.
- **Steps.**
  1. Round-trip tests for `player_to_screen` / `screen_to_player` in both modes.
  2. Draw **upper z-levels** with cut-away: fade roofs/upper walls within radius R of the player, or when `seen_cache` says the player is under a roof (`outside_cache`, `src/level_cache.h:38-40`).
  3. Directional sprites instead of rotation (`src/cata_tiles.cpp:2911-2941`).
  4. z-aware weather drops, with rain limited to `outside_cache` tiles.
  5. Optional 90° camera yaw.
- **Validation.**
  - Round-trip test over the full view in both projections.
  - Golden screenshots of the Saigon block in iso (ground, z1, roof walk).
  - Input test: each movement key maps to the expected world delta under each yaw (`get_movement_action_from_delta`, `src/action.cpp:541-576`).
- **Risk.** High on content: iso art for the Saigon set does not exist. Upper-z drawing multiplies cells, so budget it with R0 numbers.

### R4: Lighting and normal maps

- **Seam.** §5.4 G-buffer; tileset extension §5.5; `light_record` from the `generate_lightmap` scan (`src/lightmap.cpp:584-770`); a light texture from `lm` + `light_color_cache` (`src/level_cache.h:25-29`).
- **Steps.**
  - **R4a spike:** light texture through extra sampler bindings on `SDL_GPURenderState` (`src/cata_shader.cpp:195-201`) for smooth per-pixel light without normals.
  - **R4b:** normal/height/emissive atlases (loader + `compose.py`) and an N·L forward or deferred pass.

- **Validation.**
  - **Gameplay invariance:** `lit_level`/`seen_cache` bit-identical before and after (`tests/vision_test.cpp`, `[shadowcasting]`).
  - Golden screenshots: a night street with coloured neon.
  - A test that hidden tiles (`seen_cache` = 0) render black in every lighting mode (no information leak).
  - GPU time ≤ 6 ms at 1080p on an integrated GPU (UNVERIFIED target).
- **Risk.** Medium-high: art pipeline cost (normal maps for every sprite), VRAM, and visual/gameplay divergence (a tile looks lit but is `LOW` for gameplay). Mitigation: derive the visual brightness floor from `lit_level`.

### R5: Dynamic shadows

- **Seam.** `occupancy_grid` from `floor_cache`/`transparency_cache` per z (`src/level_cache.h:42-56`) plus a per-terrain `occluder_height`. `render_shadow_maps`.
- **Steps.**

  2. Point-light shadows: first reuse CPU `castLight` visibility per light as a mask, then GPU 2D shadow casting.
  3. Temporal stability (no flicker when the camera moves by one tile).
- **Validation.**
  - Golden images at 4 sun angles on the Saigon block.
  - A shadow never lights a tile that `lm` says is dark by more than 1 `lit_level` step (a consistency test on the snapshot).

- **Risk.** High: perf on integrated GPUs, and consistency with CPU lighting. Shadows are the most "cosmetic-only" feature, so they can be dropped without affecting gameplay.
